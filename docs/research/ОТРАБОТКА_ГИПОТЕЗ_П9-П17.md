## П9 подробно

Офлайн-ворота посчитаны скриптом `python -m app.ml.gates_h4` по сохранённым обучающим строкам, по одному протоколу: повтор 10×5 и отсечка ±3σ, как в проде. Результат в `backend/data/model/gates_h4.json`.

| Ворота | База | Новая модель | Порог | |
|---|---|---|---|---|
| F1, повтор 10×5 | 0,899 | 0,897 | ≥ база − 0,02 | ✓ |
| AUC | 0,991 | 0,983 | ≥ база − 0,01 | ✓ |
| LODO (Защита ИИ / Роботы / Финтех / Инфраструктура) | 1,0 / 0,92 / 0,90 / 1,0 | 1,0 / 0,83 / 0,90 / 1,0 | падение ≤ 0,10 | ✓ |
| Противоречий знаков | 3 | 0 | 0 | ✓ |
| Чувствительность к шуму ответов Jev (средний \|Δлогит\|) | 1,38 | 0,92 | ≤ 0,75 × база | ✓ |
| Профиль «только рынок» | 0,64 | 0,95 | ≥ база − 0,05 | ✓ |
| GitHub-инвариантность | Δp = −0,38 | Δp = 0 | 0 | ✓ |

Заголовочная метрика модели теперь F1 0,894 (CV5) и 0,897 ± 0,016 в повторе. Исследование предсказывало около 0,894.

На стенде `python -m app.ml.rescore_runs --since-id 11` пересчитал 44 сохранённых прогона с Jev старой и новой моделью. Медиана кандидатов с оценкой ≥ 0,5 — 10,5 → 9,5, ворота «не ниже базы − 2» пройдены. Изменения в топах заметные, но смешанные:
- **Ушло лишнее.** На перовскитах выпали «Yb-doped ZnO investigation», «doped ZnO nanostructures» и похожие. На графене выпала сама тема запроса.
- **Пришли общие названия.** В индустриальном ИИ в топ вошли «AI-based automation» и «predictive maintenance».
- **Потери.** На газлифте выпали два кандидата с оценкой около 0,55. Отдельный живой прогон 20.10 по газлифту дал 1 сигнал.

Слепую разметку «сигнал / мусор / зрелое» по списку изменений (`backend/data/model/rescore_h4.json`) должны сделать люди. Без неё ворота «мусора не больше» не закрыты.

**Режим без Jev.** На прогонах с правилами вместо Jev новая модель отсекала почти всё: 12 → 1 кандидат выше 0,5. Поэтому в этом режиме и для кандидатов, по которым Jev не ответила, используется прежняя модель `signal_model_rules.json`. Прежняя основная модель сохранена как `signal_model_prev.json`.

## П10 подробно

Режим `Run.options.seed_candidates`: GigaChat одним вызовом называет 15 «слабых сигналов» без поиска, дальше работают те же доказательства, Jev, классификатор, фильтры и паспорт. Результат в `backend/data/model/llm_baseline.json`.

| Тема | «Только LLM»: сигналов | Конвейер: сигналов | Что предлагает LLM |
|---|---|---|---|
| технология многослойного графена | 0 (1 «наблюдать») | 10 | общие «Graphene X» (солнечные элементы, суперконденсаторы, антенны), а не многослойный графен |

\* Для финтеха взят последний обычный прогон этой темы (run 40, код 19.10). На трёх остальных темах обычный прогон сделан на том же коде в тот же день.

Итог: 83% названий от LLM не прошли наши проверки (зрелость, релевантность, доказательства). Гибрид (список LLM как ещё один источник пула) не включался: по протоколу его принимают только при росте полезных элементов на отложенной выборке, а её прогон — отдельная ночная задача.

## Набор для оценки (раздел 7)

- **B1, снимки этапов.** Если задан `SNAPSHOT_DIR`, прогон сохраняет план, корпус и оценённых кандидатов. `python -m app.ml.bench redecide <снимок> [--model …]` повторяет продовый `decide()` без сети; тест подтверждает, что статусы совпадают.
- **A, списки запросов.** DEV, HOLD-OUT, регрессия, контроли, серебряные списки и зрелые контроли лежат в `backend/data/bench/queries.json` (`python -m app.ml.bench queries`). HOLD-OUT не пересекается с DEV и с примерами на главной.
- **B3, воронка.** Пул каждого прогона пишется в `stats.pool` (П11).
- **Не сделано:** судейская разметка (C), `bench_report` с бутстрэпом (G), ночные прогоны HOLD-OUT. Им нужны люди-разметчики и ночное время на ключе разработки.
