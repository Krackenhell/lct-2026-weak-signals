# Разъяснения организатора (чат задачи, по 23.09.2026)

Подтверждённой считаем только информацию от модератора задачи (Светлана). Реплики других участников — не источник.

## Проверка качества

- **Скрытого датасета нет** (20.09). Выданные 100 сигналов — это и есть материал для проверки.
- Проверка: жюри вводит открытый запрос. **По 6 темам из датасета** (индустриальный ИИ, роботы, инфраструктура ИИ, финтех, защита ИИ, edge) выдача **сравнивается с датасетом**. По остальным темам оценивают эксперты (20.09).
- **Обучающую выборку, включая отрицательные примеры, собираем сами** (16.09, 20.09).
- Команды сдают отчёт о метриках; заказчик проверяет его правдивость открытыми запросами и сверкой с датасетом (20.09). Значит, метрики должны быть честными и воспроизводимыми.
- Ограничение по времени выдачи — озвучено на Q&A, ориентир ~20 минут.

## Модели и библиотеки

- Облачные API — список из ТЗ; другие модели — после согласования с экспертами (17.09). Модератор также подтвердила, что на Q&A заказчик разрешил выходить за список при условии, что модель можно заменить (17.09).
- Лучше использовать модели, **доступные из РФ без VPN**; ограничений на open-source фреймворки нет (17.09).
- **Не использовать библиотеки, которые «из коробки» сами определяют тренды/сигналы** — главная ценность в собственном алгоритме детекции. PyTorch и т.п. можно (17.09). Код лучше писать с нуля.
- API-ключи для проверки нужно оставлять: у заказчика должна быть возможность проверить решение в любой момент (17.09).
- Серверы заказчик не даёт; хостинг любой, свои GPU-серверы можно (16–17.09).

Поля формы в личном кабинете: репозиторий (публичный, README в корне), документация, презентация (готовая, 29.09), прототип (ссылка на работающий стенд), доп. материалы (скринкаст и т.п.). Ссылки можно дублировать и нужно загрузить заранее; внешние ссылки — открыты для всех по ссылке.
