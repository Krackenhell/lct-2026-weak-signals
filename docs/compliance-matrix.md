# Соответствие требованиям задачи Газпромбанк.Тех

Требования собраны из ТЗ задачи и разъяснений организатора (`docs/organizer-clarifications.md`). Статус проверен 17.10.2026.

| Требование | Как выполнено | Где посмотреть | Статус |
|---|---|---|---|
| Ввод технологического направления в свободной форме на русском | Поле поиска; GigaChat расширяет запрос до подтем на английском и русском; без LLM — словарь направлений | Главная страница, `llm/tasks.py` | Выполнено |
| ТОП-15 зарождающихся трендов направления | До 15 позиций; если надёжных сигналов меньше — список короче, остальные во вкладке «Наблюдать» с причиной | Страница результата | Выполнено |
| Для каждого тренда: мотивация, кейс-пример, источник | Досье GigaChat: описание, преимущество, кейс-пример с номером источника, почему это ранний сигнал, применение для банка, риски; каждое утверждение проверяет decision-модель | Карточка сигнала | Выполнено (полный текст — с ключом GigaChat; без него — шаблон по источникам) |
| Атрибуты источника: название, ссылка, дата, тип, язык, уровень доверия | Все поля у каждого источника; уровень доверия по правилам с объяснением критерия; иностранные — с русским резюме и пометкой «LLM» | Карточка → «Источники» | Выполнено |
| Проверяемость источников | Живая проверка каждой ссылки в выдаче: открывается / сайт ограничивает автопроверку / не открывается; неоткрывающиеся убираются из подтверждений | Карточка → «Паспорт доказательств», `pipeline/links.py` | Выполнено |
| Отделение от зрелых технологий, стандартов и маркетингового шума | Явные фильтры с причиной: зрелое, стандарт, хайп, продукт, общая область, нерелевантно, мало подтверждений | Вкладка «Исключённые» | Выполнено |
| Методология определения зарождающегося тренда | Вопросы-признаки decision-модели + наблюдаемые показатели + интерпретируемый классификатор + паспорт доказательств | Вкладка «Методология и качество», `docs/architecture.md` | Выполнено |
| Модель «слабый сигнал / не сигнал» (этап 1) | Логистическая регрессия, обученная на 100 сигналах организатора и отрицательных примерах команды | `ml/train.py`, `data/model/` | Выполнено |
| Качество не ниже 75% | F1 0,915 (95% интервал 0,85–0,97) после переобучения с Jev 17.10 на 205 примерах с научной историей; ограничения описаны | Вкладка «Методология» | Выполнено |
| Время ответа до 20 минут | С Jev и GigaChat — 4,2–4,7 минуты на тему (шесть тем датасета, 17.10); время по этапам записывается в каждый прогон | `stats.timing` каждого прогона | Выполнено |
| Модели из списка п. 3.1 или согласованные | GigaChat (из списка); decision-модель Jev согласована экспертами 23.09.2026; локальная замена Kev | `docs/decision-models.md` | Выполнено |
| Не использовать готовые детекторы трендов | Алгоритм свой: сбор, признаки, классификатор, правила | Код | Выполнено |
| Разделение на сбор, анализ и интерфейс | `collectors` / `pipeline`, `decision`, `ml`, `llm` / `api` + `frontend` | Структура репозитория | Выполнено |
| Источники доступны из РФ без VPN | arXiv, OpenAlex, Crossref, КиберЛенинка, Europe PMC, Хабр, GDELT, GitHub, Hacker News, Википедия — проверены скриптом `scripts/check_sources.py` | Вкладка «Методология» → «Проверка источников» | Выполнено |
| Возможность проверить решение в любой момент | Стенд, Docker Compose, запуск без Docker на Windows; работает и без ключей (офлайн-правила, шаблонные досье) | `README.md`, `ЗАПУСК_и_тесты.md` | Выполнено |
| Human-in-the-loop | Кнопки решения аналитика в карточке, статистика согласия, дообучение `--with-feedback` | Карточка сигнала | Выполнено |
| Применимость для банка | Радар банка: направление, кольцо «пилотировать / изучать / наблюдать», горизонт; экспорт отчёта в Excel | Вкладка «Радар банка», кнопки экспорта | Выполнено |
| Заглянуть за горизонт: предсказательная сила | Ретроспективная проверка на срезе 2021 года (30 тем): модель — ROC-AUC 0,61, правило «больше публикаций» — 0,42, правило «быстрый рост» — 0,81 | `ml/backtest.py`, вкладка «Методология» | Выполнено; модель уступает правилу роста, направление развития описано |
