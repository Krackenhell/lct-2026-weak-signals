# Decision-модели (Jev / Kev / Laya) для скоринга слабых сигналов

Актуально на 23 сентября 2026.

## Что это

«Decision model» (System One) — модель, которая не пишет текст, а отвечает на заранее заданные типизированные вопросы по документу и возвращает вероятности:

- **noul** — да/нет с вероятностью («Есть ли у технологии массовые коммерческие внедрения?» → 0.12);
- **choice** — выбор варианта («Тип источника: научная статья / патент / пресс-релиз / блог» → распределение);
- **score** — оценка по шкале с рубрикой («Стадия зрелости 1–9 по TRL»).

Все вопросы считаются за один параллельный проход, поэтому это в десятки раз быстрее и дешевле генерации LLM.

| Модель | Кто | Лицензия / доступ | Размер | Заметки |
|---|---|---|---|---|
| [Jev](https://simonwillison.net/2026/Sep/21/jev/) | TypeSafe AI, релиз 15.09.2026 | Платный API, ранний доступ | закрыта | $0.042 / 1M входных токенов, выход бесплатно. Слаб на числах и датах, калибровка хуже заявленной ([сравнение](https://www.artifilog.com/posts/laya-vs-jev): ECE 0.246) |
| [Kev](https://github.com/jaredpalmer/kev) | open-source, на базе Qwen3.5 | Apache-2.0, [веса на Hugging Face](https://huggingface.co/collections/jaredpalmer/kev) | 0.8B / 4B / 9B | Совместимый с Jev API, есть код дообучения. Kev-9B отстаёт от Jev на ~3.5 п. (0.822 vs 0.857) |
| [Laya](https://www.artifilog.com/posts/laya-vs-jev) | Convai Innovations | Apache-2.0, self-hosted | 322M (mmBERT, мультиязычная) | Быстрее, калибровка лучше (ECE 0.081), слабее на задачах с большим числом вариантов |

## Детали по открытым аналогам (проверено 23.09.2026)

Все сравнения с Jev ниже — **цифры самих авторов** на разных бенчмарках. Независимого сравнения нет, значит качество на нашей задаче надо мерить самим.

**Kev** ([GitHub](https://github.com/jaredpalmer/kev)). Первая версия (Kev-0.5B на Qwen2.5) — через 1–2 дня после Jev, текущие модели на Qwen3.5 — 21.09.2026.

| | Точность (новые источники) | Brier (меньше — лучше) |
|---|---|---|
| Kev-0.8B | 0.852 | 0.460 |
| Kev-4B | 0.837 | 0.255 |
| Kev-9B | 0.852 | 0.237 |

Kev-9B vs Jev на dev-сплите: 0.822 vs 0.857. Маленькая 0.8B угадывает так же, но хуже откалибрована, поэтому её вероятности нужно откалибровать на своей выборке. Запуск: `uv run python -m kev.serve --run jaredpalmer/kev-4b --port 8009`, API совместим с Jev SDK. Официально поддерживает CUDA/ROCm/MLX; работа на CPU не заявлена — проверить. Дообучение 0.8B возможно на GPU с 4 ГБ, обязательно от готового чекпойнта (`--init_from`).

**Laya** ([GitHub](https://github.com/NandhaKishorM/laya), [HF](https://huggingface.co/convaiinnovations/laya)), релиз 19.09.2026, `pip install -U laya`. Чекпойнты: английский 421M (ModernBERT-large, контекст 512), мультиязычный 322M (mmBERT, 1024), typed-decisions. ~33 мс на вопрос на T4, 0.2–0.5 с на CPU.

- Заявлено 0.766 vs Jev 0.727 и ECE 0.081 — но это **после дообучения на обучающей части того же бенчмарка**.
- Без дообучения: точность 0.362, ECE 0.466. То есть Laya — быстрая основа под дообучение, а не готовый судья.
- Русский отдельно не измерялся.

```python
from laya import Router
router = Router(preload=True)
router.predict({"body": text},
               {"mature": {"type": "noul", "instructions": "Технология уже массово внедрена?"}})
```

**Вывод:** Kev — основной оценщик (работает без дообучения, база Qwen хорошо знает русский). Laya — быстрый предфильтр на CPU после дообучения на нашей разметке. Jev — эталон для сравнения, если его разрешат.

## Почему это подходит нашей задаче

ТЗ требует три вещи, которые у обычной LLM получаются плохо:

1. **Скоринг-уверенность модели** и счётчик «сигналов с уверенностью > 75%» — decision-модель сразу отдаёт вероятность, а не текст «я уверен на 80%».
2. **Интерпретируемость** — каждый вопрос к модели и есть признак. Карточка сигнала показывает: «независимое подтверждение 0.91, массовый рынок 0.08, только пресс-релиз 0.05…». Поверх — логистическая регрессия/бустинг с feature importance.
3. **Фильтрация хайпа и зрелых технологий** — это прямо классификационные вопросы, их можно прогнать по тысячам документов за секунды.

LLM остаётся только там, где нужен текст: русское резюме источника и досье сигнала — и только по найденным документам.

## Ограничение ТЗ (важно)

ТЗ п. 3.1: облачные API — только из списка (YandexGPT, Qwen3.6/Qwen3, GigaChat 2, gpt-4.1, gpt-5.6-luna). **Jev в списке нет** — его использование возможно только после согласования с экспертами Газпромбанк.Тех. Локальные модели с Hugging Face разрешены любые, значит **Kev (и Laya, если веса выложены) можно использовать без согласования**.

План: основной путь — Kev локально (0.8B/4B для ноутбука/CPU-стенда, дообучение на нашей разметке). Jev — опциональный адаптер за тем же интерфейсом, включается только после письменного согласования в чате кейса.
