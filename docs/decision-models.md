# Decision-модели (Jev / Kev / Laya) для скоринга слабых сигналов

Актуально на 23 сентября 2026.

## Что это

«Decision model» (System One) — модель, которая не пишет текст, а отвечает на заранее заданные типизированные вопросы по документу и возвращает вероятности:

- **noul** — да/нет с вероятностью («Есть ли у технологии массовые коммерческие внедрения?» → 0.12);
- **choice** — выбор варианта («Тип источника: научная статья / патент / пресс-релиз / блог» → распределение);
- **score** — оценка по шкале с рубрикой («Стадия зрелости 1–9 по TRL»).

Все вопросы считаются за один параллельный проход, поэтому это в десятки раз быстрее и дешевле генерации LLM.

## Почему это подходит нашей задаче

ТЗ требует три вещи, которые у обычной LLM получаются плохо:

1. **Скоринг-уверенность модели** и счётчик «сигналов с уверенностью > 75%» — decision-модель сразу отдаёт вероятность, а не текст «я уверен на 80%».
2. **Интерпретируемость** — каждый вопрос к модели и есть признак. Карточка сигнала показывает: «независимое подтверждение 0.91, массовый рынок 0.08, только пресс-релиз 0.05…». Поверх — логистическая регрессия/бустинг с feature importance.
3. **Фильтрация хайпа и зрелых технологий** — это прямо классификационные вопросы, их можно прогнать по тысячам документов за секунды.

LLM остаётся только там, где нужен текст: русское резюме источника и досье сигнала — и только по найденным документам.

## Ограничение ТЗ (важно)

ТЗ п. 3.1: облачные API — только из списка (YandexGPT, Qwen3.6/Qwen3, GigaChat 2, gpt-4.1, gpt-5.6-luna). **Jev в списке нет** — его использование возможно только после согласования с экспертами Газпромбанк.Тех. Локальные модели с Hugging Face разрешены любые, значит **Kev (и Laya, если веса выложены) можно использовать без согласования**.

План: основной путь — Kev локально (0.8B/4B для ноутбука/CPU-стенда, дообучение на нашей разметке). Jev — опциональный адаптер за тем же интерфейсом, включается только после письменного согласования в чате кейса.
