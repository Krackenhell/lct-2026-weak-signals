# Радар слабых сигналов — ЛЦТ 2026, задача Газпромбанк.Тех

Сервис по открытому запросу — широкому («перспективные решения в финтехе») или узкому («технологии многослойного графена», «газлифт в скважинах») — находит в открытых источниках **ранние научно-технологические тренды**, отделяет их от зрелых технологий, стандартов и тем без технического подтверждения и формирует **топ-15 слабых сигналов** с объяснением, уверенностью модели и проверяемыми источниками.

**Ключевая идея.** GigaChat (отечественная LLM) понимает запрос, извлекает названия технологий и пишет справку. Признаки слабого сигнала извлекает decision-модель **Jev** (TypeSafe AI; использование согласовано с экспертами Газпромбанк.Тех) или её локальный аналог **Kev**: за один проход она отвечает степенью от 0 до 1 примерно на 17 вопросов о текстах источников («есть ли массовое внедрение», «это стандарт», «ранняя ли стадия»…) и проверяет каждый документ. Итоговое решение принимает **наш интерпретируемый классификатор** на ответах Jev и наблюдаемых показателях; каждая позиция объясняется вкладами признаков. Всё остальное — собственный код: сбор из 29 открытых источников, поиск растущих поднаправлений, паспорт доказательств, машина времени.

### Что сделали мы и что делают модели

На один запрос — около 50 вызовов Jev и около 28 вызовов GigaChat против детерминированной обработки 1 000+ документов нашим кодом.

| Компонент | Как устроен | Файл | Тесты | Что было бы при подходе «только LLM» |
|---|---|---|---|---|
| Сборщики ~30 источников | robots.txt, паузы по сайтам, предохранитель, кэш, повторы | `backend/app/collectors/` | `test_collectors.py`, `test_news_sources.py` | Источников нет — названия из памяти модели |
| Планировщик запроса | правило «широкий / узкий», перевод по корням, кэш плана | `llm/tasks.py` | `test_hypotheses.py`, `test_llm_tasks.py` | Подтемы модели: 50–73% не находятся в литературе (A/B 19.10) |
| Растущие поднаправления | рост доли ключевых слов OpenAlex + специфичность | `pipeline/subtopics.py` | `test_subtopics.py` | Нет |
| Маршрут источников | профиль запроса → Europe PMC / ML-источники | `pipeline/routing.py` | `test_hypotheses.py` | Нет |
| Майнинг фраз и склейка синонимов | n-граммы, основы слов, разнообразие с учётом запроса | `pipeline/discovery.py`, `decide.py` | `test_hardening.py` | Дубли и сама тема в списке |
| Признаки и классификатор | 18 признаков, логистическая регрессия, калибровка, знаки по смыслу, ворота | `ml/train.py`, `ml/gates_h4.py` | `test_train.py` | Нет вероятностной оценки и объяснения |
| Паспорт и проверки доказательств | независимость источников, «k из 5», лестница «почему рано» | `pipeline/passport.py` | `test_verifiability.py` | Нет проверки, что источник вообще есть |
| Проверка справки | каждое утверждение — Jev, дословные цитаты сверяются | `pipeline/passport.py` | `test_pipeline_models.py` | Утверждения без проверки |
| Машина времени | 118 тем, 5 отсечек, проверка «вне времени», импульс роста | `ml/timemachine.py`, `ml/emergence_check.py` | `test_timemachine.py` | Нет |
| Защита и учёт | SSRF/путь к файлам, лимиты живого поиска, стоимость | `main.py`, `api/routes.py`, `pipeline/cost.py` | `test_api.py`, `test_stress.py` | — |

Словарь направлений пересекается примерно с 40 терминами датасета организатора, поэтому после П1 он служит только запасным путём для широких запросов. Замер «только LLM против конвейера» — `backend/data/model/llm_baseline.json`.
### Новое к финалу: от сигнала к рынку

| Возможность | Что видит пользователь | Как устроено |
|---|---|---|
| Лестница «от науки до рынка» | Ступени: научная работа → патент → грант → стартап → раунд → пилот → контракт → серийный продукт → закупка в России, с первой датой и примером | Документы кандидата и открытый веб-поиск (Brave Search API); каждую ступень подтверждает Jev (`pipeline/market.py`) |
| Доводы «против» | Сообщения о провале, отказе или массовости технологии рядом с доводами «за» | Веб-поиск + вопрос Jev «говорит ли документ о провале или массовости» |
| Карта игроков | Организации мира и России, компании из подтверждений | OpenAlex по работам за 2 года; российские организации — только с российской аффилиацией |
| Под вашу компанию | Загрузили стратегию или ТЗ — видно, какие сигналы связаны с документом, и цитата абзаца | TF-IDF без LLM и GPU, документ не сохраняется (`pipeline/context.py`) |
| Подписка на тему | Пересчёт раз в неделю и сводка: новые, выпавшие, усилившиеся сигналы | `pipeline/watch.py`, страница «Подписки»; включается `SUBSCRIPTIONS_EVERY_HOURS` |
| Прогноз с проверкой | Прогноз по каждому сигналу фиксируется на дату и через полгода проверяется сам по заранее записанному критерию | `pipeline/forecasts.py`, сводка на странице «Методология» |
| Выдача по мере подтверждения | Подтверждённые кандидаты видны во время расчёта | Кандидат с оценкой ≥ 0,5, паспортом A/B и релевантностью ≥ 0,5 — сразу в «предварительные» |
| Слепой замер | Доля полезных карточек по разметке людей, наш конвейер против «только LLM» | `ml/blind_eval.py`: лист для разметчиков без оценок и происхождения, подсчёт и согласие разметчиков |

**Источники, подключённые 20.10** (ключи — только в `.env`):

| Источник | Для чего | Ключ |
|---|---|---|
| PubMed (NCBI E-utilities) | рецензируемая биомедицина — корпус и доказательства для наук о жизни | `NCBI_API_KEY` |
| bioRxiv / medRxiv | свежие препринты наук о жизни: каталог за 7 дней загружается в фоне раз в сутки, поиск по нему локально | не нужен |
| NASA ADS | физика, материалы, энергетика | `NASA_ADS_TOKEN` |
| Stack Exchange | вопросы инженеров по технологии — ступень «сообщество» | `STACKEXCHANGE_KEY` |
| ClinicalTrials.gov | клинические исследования — ступень «пилот / испытания» | не нужен |
| SEC EDGAR | форма D — «раунд», отчёты 8-K / 10-K / S-1 — «серийный продукт» | `SEC_USER_AGENT` (название и почта) |
| Роспатент | российские патенты — ступень «патент» | `ROSPATENT_API_KEY` |
| ЕИС госзакупок (RSS) | закупки — ступень «закупка в России» | не нужен |

Запрос к каждому реестру — не дольше 20 секунд и параллельно: недоступный реестр не задерживает прогон. SEC, Роспатент и ЕИС бывают недоступны из части сетей (SEC отвечает 403), их стоит проверить со стенда.

Brave Search: бесплатный ключ (1 запрос в секунду, 2000 в месяц) задаётся `BRAVE_API_KEY`. Бюджет — не больше 30 запросов на прогон, кэш ответов — 10 суток. В признаки классификатора результаты веб-поиска не входят.
### Проверяемость вывода (доработка к финалу)

| Что | Как работает | Код |
|---|---|---|
| Проверка запроса | GigaChat определяет, технологическое ли это направление; без LLM — прозрачные правила. На «Привет» — честный отказ, а не 15 «сигналов» | `llm/tasks.py` → `check_query` |
| Релевантность к исходному запросу | Jev оценивает кандидата и к теме плана, и к формулировке аналитика; берётся меньшая оценка | `questions.py`, `decide.py` |
| Паспорт доказательств A/B/C | В том же вызове Jev проверяет **каждый документ**: описывает ли он именно эту технологию; считаются подтверждённые документы, независимые домены, наука. Меньше 3 подтверждений из 2+ источников — кандидат уходит в «Наблюдать» | `pipeline/passport.py` |
| Самое твёрдое событие | Типизированный вопрос Jev: статья → прототип → грант → пилот → релиз → раунд инвестиций | `questions.py` → `EVENT` |
| Перекрёстная проверка досье | GigaChat пишет, Jev проверяет каждое фактическое утверждение; неподтверждённое удаляется, цитаты сверяются дословно | `passport.py` → `apply_verification` |
| Запас прочности | Точный пересчёт линейной модели: вероятность без самого сильного довода «за» | `passport.py` → `robustness` |
| Окно для России | Научная активность в мире против упоминаний на Хабре и в русскоязычных СМИ | `passport.py` → `russia_window` |
| Мониторинг темы | Повторный прогон того же запроса показывает, что появилось и что выпало | `runner.py` → `_changes` |
| Растущие поднаправления | Для узких тем: ключевые слова OpenAlex, доля которых в работах по теме быстро растёт и которые специфичны для темы (графен → «rhombohedral graphene», «chiral superconductivity»); без LLM ключевой термин переводится через Википедию | `pipeline/subtopics.py` |
| Калибровка оценки | Температура подбирается по прогнозам на невиденных примерах; выше 95% не показывается; признаки вне диапазона обучения помечаются | `ml/train.py`, `ml/model.py` |
| Русские термины | Глоссарий и проверка калек («закаливание подсказок» → «защита промптов от атак») | `llm/terms.py` |
| Честная оценка | Обучение и проверка только на примерах с научной историей (OpenAlex находит хотя бы одну работу), 95% интервалы, повтор 5×10, ограничения | `ml/train.py` |
| Машина времени 2.0 | 118 тем, 5 дат среза 2016–2022, проверка «вне времени» | `ml/timemachine.py` |

По умолчанию — чистое обнаружение (`USE_WATCHLIST=false`); база отслеживания включается как режим мониторинга.

### Ограничения, о которых честно
- Отрицательные примеры собраны командой; пограничных случаев мало — метрики остаются верхней оценкой. Трудные негативы (`"hard": true` в `negatives.json`) войдут при полном переобучении с ключом Jev.
- Из 100 сигналов организатора по 62 открытые источники дают меньше 3 документов — на них модель не обучается и не оценивается; в живом поиске такие кандидаты попадают в «Наблюдать».
- Перенос на новую область считается на 20–30 примерах — интервалы широкие.
- Признак «самое твёрдое событие» входит в классификатор (обучающая выборка переопрошена Jev). GitHub и Hacker News в классификатор не входят (П9: вне IT «ноль репозиториев» превращался в бонус) — они остаются документами-доказательствами.
- По узким отраслевым темам независимых источников мало: часть кандидатов остаётся «под наблюдением», пока не наберётся 3 подтверждённых документа.

### Время работы
| Этап | Время |
|---|---|
| Обработка новой темы (ТОП-15 + досье) | 2–4 минуты (замер 19.10: «газлифт в газоконденсатных скважинах» — 2 мин 14 с); требование — до 20 минут |
| Темы-примеры с главной (11 тем, `backend/app/examples.py`) | около 1 с: **рассчитаны заранее** (`POST /api/precompute` или `python -m app.precompute`), дата расчёта видна на странице, «Пересчитать» запускает анализ с нуля. Повторно отдаётся только годный результат: та же версия конвейера и моделей, без сбоя Jev или OpenAlex, план от LLM (срок — `REUSE_HOURS`, по умолчанию 96 ч) |
| Подготовка модели: сбор доказательств для 240 обучающих примеров | ~30 минут, выполняется один раз заранее (`python -m app.ml.train`) |
| Переобучение классификатора по сохранённым признакам | секунды (`--refit`), переопрос decision-модели — ~1 минута (`--reask`) |

## Быстрый старт (Docker)

Требуется Docker с Compose v2.

```bash
git clone https://github.com/Krackenhell/lct-2026-weak-signals.git
cd lct-2026-weak-signals
cp .env.example .env        # при необходимости укажите ключи моделей
docker compose up -d --build
```

Откройте http://localhost (порт меняется переменной `HTTP_PORT`).

Без ключей система работает полностью: decision-модель — на словарных правилах (`DECISION_PROVIDER=heuristic`), досье — по шаблону (`LLM_PROVIDER=none`). Для полного качества укажите в `.env`:

| Переменная | Значение |
|---|---|
| `DECISION_PROVIDER=jev` + `TYPESAFE_API_KEY` | Jev (облачный API TypeSafe) |
| `DECISION_PROVIDER=kev` + `KEV_BASE_URL` | Локальный Kev (см. ниже) |
| `LLM_PROVIDER=gigachat` + `GIGACHAT_AUTH_KEY` | Досье и резюме на русском через GigaChat 2 |
| `LLM_PROVIDER=yandexgpt` + `YANDEX_API_KEY`, `YANDEX_FOLDER_ID` | YandexGPT 5 |
| `OPENALEX_API_KEY`, `GITHUB_TOKEN` | Повышенные лимиты источников (необязательно) |

Проверка: `curl http://localhost/api/health` → `{"status":"ok"}`.

## Развёртывание стенда на сервере

Рекомендуемая конфигурация: Ubuntu 22.04/24.04, 4 vCPU, 8–16 ГБ RAM, 40 ГБ SSD, публичный IP, открыт порт 80. GPU не нужна.

```bash
curl -fsSLO https://raw.githubusercontent.com/Krackenhell/lct-2026-weak-signals/main/deploy/setup-ubuntu.sh
bash setup-ubuntu.sh            # первый запуск создаст /opt/weak-signals/.env — заполните ключи
bash setup-ubuntu.sh            # второй запуск соберёт и поднимет стенд
```

Контейнеры перезапускаются автоматически (`restart: unless-stopped`), в том числе после перезагрузки сервера.

## Локальная разработка без Docker

```bash
# backend (Python 3.11+); по умолчанию SQLite в backend/data/local.db
cd backend
python -m venv .venv && . .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000

# frontend (Node 20+), в другом терминале
cd frontend
npm install
npm run dev          # http://localhost:5173, /api проксируется на :8000
```

## Обучение и оценка модели (этап 1)

```bash
cd backend
python -m app.ml.train            # сбор доказательств для 240 примеров (~30 мин, с кэшем) + обучение
python -m app.ml.train --reask    # переопросить decision-модель по сохранённым доказательствам (например, после подключения Jev)
python -m app.ml.train --refit    # только переобучить классификатор
```

Результаты: `backend/data/model/signal_model.json` (веса), `metrics.json` (Precision / Recall / F1, абляция, перенос на новую область), `training_rows.json` и `training_evidence.json` (признаки и доказательства для воспроизводимости). Отчёт также на странице «Методология и качество».

## Локальный Kev (необязательно)

## Как работаем вдвоём

Оба участника пишут код по очереди. Состояние всегда в `main`: после каждого завершённого шага — коммит и push, чтобы работу можно было продолжить с любого компьютера. Ключи API хранятся только в `.env`, он не попадает в git.
